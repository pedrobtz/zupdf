# Test fixtures

Written by `tools/update-fixtures`; nothing here is edited by hand.

| File | Source | Licence |
|---|---|---|
| `afl-input/*.pdf` | pdfio's `afl-input/` at the commit pinned in `src/vendor/PROVENANCE`: PDFs from Apache PDFBox's issue tracker that pdfio fuzzes with. Some are malformed. | Apache-2.0, as distributed with pdfio |
| `testpdfio.pdf` | pdfio's `testfiles/testpdfio.pdf` from the pinned release tarball | Apache-2.0 with pdfio's exceptions |
| `OpenSans-Regular.ttf` | pdfio's `testfiles/`, the Open Sans font | Apache-2.0, `OpenSans-LICENSE.txt` beside it |
| `pdfio-color.png`, `pdfio-rgba.png`, `color.jpg` | pdfio's `testfiles/`, for the writer's image tests | Apache-2.0 with pdfio's exceptions |
| `fuzz/*.pdf` | Inputs `tools/run-fuzz` found that crashed or hit undefined behaviour, kept as regressions once fixed: `xref-w-negative.pdf`, a negative `/W` entry (patch 0007); `firstchar-huge.pdf`, a `/FirstChar` past any integer (`zpd_clamp_int()`); `repair-loop.pdf`, a damaged file pdfio's repair looped on for ever (patch 0008); `cmap-empty-name.pdf`, an empty name in a ToUnicode CMap (the lexer's buffer); `xref-index-huge.pdf`, an `/Index` entry past any integer (patch 0009); `xref-generation-shift.pdf`, a four-byte generation with its top bit set in a cross-reference stream (patch 0017); `object-value-leak.pdf`, an object whose value is a hex string, read twice by the repair scan, which leaked (patch 0011); `trailer-not-dict.pdf`, a trailer that is a hex string, which leaked when refused (patch 0012); `objstm-value-leak.pdf`, a hex-string object read by the repair scan and again from an object stream, which leaked (patch 0013); and, written by the tests' `page_pdf()` rather than found by the fuzzer, `content-nan.pdf`, a content stream whose numbers overflow to Inf and its matrix to NaN (#41), and `forms-shared.pdf`, three levels of forms each drawing the next a hundred times, read once each and walked 10 101 times (#31); and `xobject-unloadable.pdf`, the fuzzer's variant of it whose innermost form pdfio cannot load, which was parsed again at each of 10 000 draws (#31) | MIT (zupdf); generated by libFuzzer from the afl-input seeds, or by `page_pdf()` |
| `corpus.tsv` | What `read_corpus()` in `helper-pdf.R` gives for each `afl-input` and `fuzz` file, or `NA` for one `pdf_open()` refuses; regenerated by hand from `read_corpus()` when a pdfio or extractor change moves a row, with the reason in the commit | MIT (zupdf) |
| `encrypted-rc4-128.pdf`, `encrypted-aes-128.pdf` | Written by pdfio through `tools/fixtures/make-encrypted.c`: one page, no password, all permissions | MIT (zupdf) |
| `encrypted-rc4-128-pw.pdf`, `encrypted-aes-128-pw.pdf` | As above, with user password `user`, owner password `owner`, printing forbidden | MIT (zupdf) |
| `grdevices.pdf` | `grDevices::pdf()`, one plot | MIT (zupdf) |
| `cairo.pdf` | `grDevices::cairo_pdf()`, one plot. Written only where `cairo_pdf()` loads; not committed, because the machine that last ran `tools/update-fixtures` had no cairo, and no test reads it | MIT (zupdf) |

Encryption keys are random, so regenerating the encrypted files changes
their bytes but not what the tests read from them.
